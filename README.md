# WorkTime — ניהול זמן עבודה ל-Windows

תוכנה קומפקטית, מהירה וקלה לתיעוד שעות עבודה, ניהול לקוחות ופרויקטים, דוחות ותשלומים — עם שליטה
מלאה מתוך התפריט של סמל התוכנה בשורת המשימות, ושעון צף מינימליסטי על המסך.

נבנתה ב־**Tauri 2 + Rust + React + TypeScript** ומשתמשת ב־**SQLite** מקומי. אין שרת, אין תלות
בענן, והנתונים נשארים במחשב שלכם.

תיעוד מלא של הפרויקט — מה נבנה, מה נבדק, תהליך השחרור והצעות המשך — נמצא ב־[PROJECT-LOG.md](PROJECT-LOG.md).

## למה זה קל וקטן

| | WorkTime |
|---|---|
| מנוע | Tauri 2 (Rust) + WebView2 של Windows |
| מסד נתונים | SQLite מוטמע (ללא התקנה) |
| מתקין | קטן משמעותית מאפליקציית Electron מקבילה (NSIS / MSI) |
| זיכרון בזמן עבודה | נמוך — מבוסס WebView2 המשותף עם המערכת, ללא תהליך דפדפן נפרד |
| תלויות צד-שלישי בצד הלקוח | אין |

ה-UI נבנה בלי ספריות רכיבים ובלי ספריות גרפים — כל הרכיבים והתרשימים הם קוד שלנו, כדי לשמור על
גודל קטן ועל שליטה מלאה בעיצוב.

## מה יש בפנים

### עבודה ותיעוד זמן
- טיימר חי עם פרויקט, לקוח ותיאור; חישוב שווי בזמן אמת.
- התחלה מהירה של פרויקט מהתפריט בשורת המשימות (8 הפרויקטים האחרונים).
- רשומות ידניות, עריכה ומחיקה, סימון "לחיוב" ו"שולם".
- עיגול דקות (5/10/15/30), סגירה אוטומטית של טיימר שנשכח.

### לקוחות, פרויקטים ופרופילים
- כרטיסי לקוח עם פרטי קשר, תעריף, שעות וחוב פתוח.
- פרויקטים עם לקוח, סטטוס, תעריף, תקציב והתקדמות מול התקציב.
- מספר פרופילים נפרדים (עבודה / פרילנס / עסק) עם הפרדת נתונים מלאה, כולל מעבר מהיר מהתפריט.

### כספים ודוחות
- דוח לפי טווח תאריכים עם פילוח לפי יום, לקוח ופרויקט.
- סה"כ שעות, שעות לחיוב, סכום לחיוב, שולם וממתין לתשלום.
- ייצוא CSV עם תמיכה בעברית (BOM לאקסל).
- רישום תשלומים, כולל סגירה גורפת של שעות מחויבות כשולמו.

### חוויית שימוש
- ערכת נושא כהה/בהירה/לפי Windows, עברית מלאה עם RTL.
- שעון צף שקוף, תמיד מעל החלונות, ניתן לגרירה, עם כפתור התחל/עצור.
- התראות Windows + מרכז התראות: תזכורת כשהטיימר כבוי, יעד יומי, עדכוני גרסה וגיבויים.
- הפעלה אוטומטית עם Windows (אופציונלי) וסגירת חלון שמשאירה את התוכנה ברקע.

## התקנה

### הורדה
פתחו את [דף המהדורות](../../releases) והורידו את `WorkTime_<version>_x64-setup.exe` (NSIS) או
`WorkTime_<version>_x64_en-US.msi`. ההתקנה היא למשתמש הנוכחי ואינה דורשת הרשאות מנהל.

### בנייה מהמקור (Windows)
דרישות: Node.js 18+, Rust stable, Microsoft Visual Studio Build Tools (C++), WebView2 (קיים
ב-Windows 10/11).

```bash
npm install
npm run tauri build
```

המתקינים ייווצרו תחת `src-tauri/target/release/bundle/`.

### פיתוח
```bash
npm install
npm run tauri dev
```

## גיבוי ל-Google Drive

הגיבוי הוא קובץ JSON אחד עם כל הנתונים (פרופילים, לקוחות, פרויקטים, שעות, תשלומים והגדרות —
ללא סודות). הקובץ נשמר בתיקיית `WorkTime Backups` בדרייב, ונשמרים 30 הגיבויים האחרונים.

1. היכנסו ל-[Google Cloud Console](https://console.cloud.google.com/) וצרו פרויקט.
2. הפעילו **Google Drive API** (APIs & Services → Library).
3. הגדירו **OAuth consent screen** מסוג External והוסיפו את עצמכם כ-Test user.
4. תחת **Credentials → Create credentials → OAuth client ID** בחרו **Desktop app**.
5. העתיקו את ה-**Client ID** וה-**Client Secret** אל תוך WorkTime → הגדרות → גיבוי ושחזור.
6. לחצו **התחברות ל-Google Drive** ואשרו בדפדפן.

ההרשאה המבוקשת היא `https://www.googleapis.com/auth/drive.file` בלבד — גישה רק לקבצים
שהתוכנה עצמה יצרה. אפשר להפעיל גיבוי אוטומטי כל N שעות, ולשחזר גיבוי בלחיצה (השחזור מחליף את
הנתונים הנוכחיים).

> טוקן הרענון נשמר בקובץ מקומי בתיקיית הנתונים של האפליקציה (`gdrive-token.json`) ואינו נשלח
> לשום מקום מלבד Google.

## עדכוני גרסה מתוך התוכנית

בהגדרות → **עדכוני גרסה** מוגדר המאגר (`owner/repo`). התוכנה קוראת את
`GET /repos/{repo}/releases/latest` ומציגה:

- האם קיימת גרסה חדשה (השוואת semver),
- שם המהדורה, תאריך פרסום והערות הגרסה המלאות,
- קובצי ההתקנה הזמינים (MSI/EXE) עם קישור הורדה ישיר.

ברירת המחדל: בדיקה אוטומטית פעם ב-12 שעות ברקע, עם התראה כשמתפרסמת גרסה חדשה.

### פרסום גרסה חדשה

פקודה אחת מעדכנת את מספר הגרסה בכל המקומות, פותחת קטע חדש ב־`CHANGELOG.md` ומריצה את בדיקת
הבנייה (typecheck + build של ה-frontend, בדיוק כמו ב-CI):

```bash
npm run release:prepare -- 1.0.1
```

הסקריפט מעדכן את `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`
ו־`src-tauri/Cargo.lock`, ומוסיף ל־`CHANGELOG.md` כותרת `## [1.0.1] — <תאריך>` עם שורת `TODO`.
כתבו שם את השינויים — הטקסט הזה הוא בדיוק מה שמוצג בהערות הגרסה ובתוך התוכנה.

אחר כך דחפו את התג, וה-workflow בונה ומפרסם:

```bash
npm run release:check
git add -A && git commit -m "Release v1.0.1"
git tag v1.0.1
git push origin main v1.0.1
```

`npm run release:check` מאמת שארבעת הקבצים נושאים אותה גרסה, שקטע ה־CHANGELOG קיים ואינו מכיל
`TODO`, ושם התג תואם לגרסה. הבדיקה רצה גם בתוך ה-workflow לפני הבנייה — כך שגרסה לא עקבית או הערות
חסרות לא יפורסמו כתג.

`npm run release:check` הוא גם כלי אבחון: אם משהו לא מסונכרן הוא מפרט בדיוק איזה קובץ נשאר מאחור.

## מבנה הפרויקט

```
src/                    ממשק React (עברית, RTL)
  components/           רכיבי UI ואייקונים (ללא ספריות חיצוניות)
  views/                לוח בקרה, יומן, לקוחות, פרויקטים, דוחות, תשלומים, התראות, פרופילים, הגדרות
  lib/                  שכבת API מול Rust, טיפוסים, פורמט ותצוגת מצב
  floating.tsx          חלון השעון הצף
src-tauri/
  src/db.rs             סכימה, מיגרציות, הגדרות וברירות מחדל
  src/commands.rs       כל פקודות ה-backend
  src/tray.rs           תפריט שורת המשימות
  src/reminders.rs      תזכורות והתראות רקע
  src/gdrive.rs         OAuth2 + Drive API
  src/backup.rs         ייצוא/ייבוא JSON
  src/updates.rs        בדיקת מהדורות GitHub
scripts/make-icons.mjs  יצירת אייקונים ללא תלויות
scripts/release.mjs     עדכון גרסה בכל הקבצים, קטע CHANGELOG ובדיקות שחרור
```
